# 计划：年轻活力版数据工作台 UI 优化

## 目标

把当前前端从偏展示型、文案较多的页面，优化成更简洁、年轻、活力、真实可用的数据管理工作台。

重点是减少冗余模块和装饰感，突出上传、数据资产列表、详情预览、下载、删除这些核心操作，让页面更像一个轻量 SaaS 工具，而不是介绍页。

## 范围

- 优化 `internal/web/index.html`
- 优化 `internal/web/styles.css`
- 必要时小幅调整 `internal/web/app.js` 的状态文案和渲染结构
- 保留现有 API 调用和后端行为
- 保留上传、刷新、列表、详情、下载、删除的完整流程
- 在页面上更明确地呈现当前是 PostgreSQL 元数据存储，避免再把 `data/lumino.db` 作为数据库入口

## 不做什么

- 不引入 React/Vue/Next 等新框架
- 不引入大型 UI 组件库
- 不改变后端 API
- 不提交 `data/lumino.db`、上传文件或 `.cache/` 运行时缓存
- 不把本地数据目录纳入 Git 管理

## UI/UX 方向

基于 `ui-ux-pro-max` 查询结果，采用：

- 风格：Data-Dense Dashboard + Bento Box Grid
- 情绪：年轻、轻快、简洁、数据工具感
- 布局：减少 hero 占比，首屏直接进入工作台
- 色彩：干净浅底，使用蓝色作为可信数据主色，加入少量青绿/琥珀/亮色强调，避免单一蓝色页面
- 交互：150-300ms 过渡、清晰 hover/focus、按钮和列表项有明确状态
- 响应式：375px、768px、1024px、1440px 视口不横向溢出

## 实现步骤

1. 重构首屏信息层级
   - 移除偏营销的能力卡片
   - 压缩顶部说明区
   - 把上传、资产列表、关键指标放到首屏核心区域

2. 优化视觉系统
   - 更新 CSS 变量和配色
   - 降低大面积蓝色/渐变/装饰元素
   - 使用更清爽的白底、浅灰底、青绿/琥珀点缀
   - 保持卡片圆角不超过现有约束，避免过度圆润

3. 优化工作台布局
   - 上传面板更紧凑
   - 数据列表更利于扫描
   - 详情区突出字段、数值统计、样例数据
   - 下载和删除动作保持清晰可见

4. 优化微交互和状态
   - 按钮 hover/focus/disabled 状态统一
   - 列表选中态更明显但不过重
   - 上传中、空列表、错误状态文案更短
   - 删除确认流程保持现有安全边界

5. 保持可用性和可访问性
   - 所有输入继续有 label
   - 键盘 focus 可见
   - 移动端不出现横向滚动
   - 表格在窄屏保持可滚动或可阅读

## 数据与 API 变化

- 不改变 API。
- 不改变数据库表结构。
- 不改变上传、下载、删除逻辑。
- PostgreSQL 保存元数据。
- `data/` 只保存上传文件和旧 `metadata.json` 迁移备份，继续被 `.gitignore` 忽略。

## 验证方式

1. 静态检查
   - `git diff --check`

2. Go 测试
   - `GOPATH=/Users/ekko/resp/Lumino/.cache/go-path GOCACHE=/Users/ekko/resp/Lumino/.cache/go-build .cache/go-toolchain/go1.26.2/bin/go test ./...`

3. 接口冒烟
   - `GET /api/health`
   - `GET /api/datasets`
   - 上传 CSV
   - 获取详情和 preview
   - 下载文件并比对内容
   - 删除测试数据
   - 删除后详情返回 404

4. 前端人工测试
   - 打开 `http://127.0.0.1:18080`
   - 测试刷新按钮
   - 测试上传表单
   - 测试选择文件后的文件名显示
   - 测试数据列表选择
   - 测试详情预览
   - 测试下载按钮
   - 测试删除按钮和取消/确认路径
   - 在窄屏和桌面宽度检查布局

## 风险与待确认

- 这是视觉和布局调整，可能会改变你对当前页面的信息密度感受，需要以真实使用流程验收。
- 页面会更像工具台，减少介绍型内容；如果你还希望保留品牌/宣传感，需要确认保留比例。
- 不会提交 PostgreSQL 数据或本地上传文件。如果你希望仓库里有示例数据，需要另外设计 seed/sample 数据方案。
